### 4.3 Plans per stream

Every stream works test-first: write the failing check, see it fail, make it pass. "CI" means the runner, never the laptop.

#### R1: Native gate sharding (start now; no owner gate)
- **Why:** the native gate takes 30–34 min against a 45 min limit, and every PR waits on it. This session alone lost hours to it.
- **Plan:**
  1. Record the current collection: `pytest --collect-only -q` inside the verification image, giving the test count and IDs.
  2. Split the job into a matrix of 3 shards. Use `--splits/--group` from `pytest-split`, pinned, or a deterministic split by file hash; do not add a heavy plugin without pinning.
  3. Add a final "sum" job that fails unless the shards' passed + skipped + deselected totals equal the recorded collection count. At `5b804db` that was 4047 passed, 18 skipped, 1 deselected, and it grows as tests are added. Collect it fresh in the same run.
  4. Build the verification image once and share it between shards (`docker save` to an artifact, or the GHA cache).
- **Acceptance:**
  - wall-clock ≤ 15 min;
  - the same test IDs run, with the union of shard IDs equal to the collected IDs;
  - a deliberately failing test in any shard fails the PR;
  - the timeout is unchanged at 45 per shard.

#### R2: Pinned release images (B14 step 15)
- **Why:** `backend/Dockerfile` uses a floating `continuumio/miniconda3` and an unpinned CadQuery. Verification used `Dockerfile.verify` (`python:3.10-slim-bookworm`, pinned). What ships must equal what was verified.
- **Plan:**
  1. Write a test, `e2e/test_image_pins.py`, run in CI. It parses each Dockerfile and lock, and fails on any unpinned `FROM` (it must carry `@sha256:`) or any unpinned requirement.
  2. Rebase the backend image on the verification dependency set, keeping the OS and native libraries (libGL for OCP) and the UID/GID 10001 user.
  3. Pin the frontend Python deps and the Node explorer build. Bundle the viewer assets locally, with no CDN at runtime.
  4. Keep the production XFOIL configuration distinct from `mock_xfoil`.
- **Acceptance:**
  - the pin test passes;
  - both images build in CI from a clean checkout;
  - `pip check` is clean inside each image;
  - the native gate passes against the new backend image (or against `Dockerfile.verify` if R1 hasn't merged);
  - the image digests are recorded.

#### R3: Release compose and startup guards (B14 step 16)

### 5.3 Lead's merge protocol

1. `gh pr checks <N>`: every check passes on the **current head**.
2. **Skip-count check:** compare `N passed, M skipped` with main's last run. If skips rose, find out which tests skipped before merging; new tests must run.
3. **Security review:** required when the § 4.2 column says yes. If findings come back, send them to the workstream agent, then run a **verification re-review** of the fix diff (`git diff <old> <new>` saved to the scratchpad). Merge only when no CRITICAL, HIGH or MEDIUM is open. LOW items are either fixed or recorded in the handoff.
4. Merge with `gh pr merge <N> --merge`, pull, and check main's CI on the merge commit.
5. Remove the worktree and branch, and delete the remote branch.
6. Report to the owner after each merge batch:
   - what merged;
   - CI evidence;
   - what wasn't verified;
   - the next step.
