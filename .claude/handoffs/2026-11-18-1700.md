### 5.3 Merge protocol

1. `gh pr checks <N>`: all checks pass on the **current head**.
2. **Skip counts.** Sum the shard `passed`/`skipped` and compare with main's last run.
   - Main at `e2370cc` was about 4126 passed / 17 skipped. #78 adds a few skips by design: the Dockerfile checks skip inside the native image via `MIRUM_NATIVE_GATE_IMAGE=1`.
   - If skips rise unexpectedly, find the test before merging. The shard reports carry counts but not IDs (§ 8).
3. **Security review** where required.
   - Send the findings back to the agent.
   - Then run a **verification re-review** of `git diff <old> <new>`, limited to the stream's files when main was merged in.
   - Merge only when no CRITICAL, HIGH or MEDIUM is open.
   - LOW items are either fixed or recorded in the handoff.
4. `gh pr merge <N> --merge`, pull, then remove the worktree and branch and delete the remote branch.

### 5.5 Lessons from this session (apply them)

- **Agent stalls and context bloat.**
  - Agents past about 150–200k tokens of context stalled repeatedly.
  - Start a **fresh agent per stream or follow-up PR** with a concise brief and the diagnosed problem, rather than resuming a bloated one.
  - Rate limits also stop agents mid-task; resume them with SendMessage after the reset.
- **Check the arithmetic yourself.** One "extra test" turned out to be an earlier baseline taken from a branch run instead of main.
- **Real catches came from review plus verification:**
  - a fail-open on `MIRUM_DEPLOYMENT`;
  - a token printed in pytest tracebacks;
  - a skip guard a PR could defeat by deleting a workflow file;
  - `.dockerignore` ignored under the bake git context.
- **Windows:** Avast intercepts TLS on the laptop, so nothing live runs locally. Python edit scripts can write CRLF; use `newline=''`.
