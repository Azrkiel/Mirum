## 6. What went badly and why

- **Merged #33 on one green PR run; `main` went red.** The CEM receipt test hashes exact floats, and hosted runners differ in the last bits. The fix took two more PRs. Lesson: for anything float-hash or runner-sensitive, require a green run on `main` (or two runs) before calling it fixed.
- **CI watchers never fired.** They used `jq`, which Git Bash lacks. Use `gh ... --json X --jq '...'` (gh's built-in jq) instead.
- **Low RAM, about 2–3 GB free.** Claude Code killed a background watcher under memory pressure. Docker is unusable for D7 until RAM frees up.
- **Subagents stalled at long CI waits** (600 s watchdog) twice, losing their final reports. Make agents write the report before waiting, then append the CI result.
- **Deleting a merged base branch auto-closed the stacked PR #34.** It was fixed by restoring the base, reopening, retargeting to `main` and deleting the base again. Retarget stacked PRs before deleting their base.
- **One subagent wrote code before tests**, against the brief.

## 8. Decisions, rationale, and invariants

- **Checked design is the integration model.** The LLM only fills a bounded brief, a human reviews the exact revision, and a deterministic solver decides. The LLM never writes geometry for a registered capability.
- **The job system is the checked-design job store.** The May `/jobs` branch was dropped.
- **AI draft mode stays off** (`MIRUM_ENGINEERING_AI_DRAFTS` unset) until B13 passes.
- **`MIRUM_TRUSTED_CLIENT_HEADER` may only be on while `mirum-api` is private** (Flycast only). If the backend ever becomes public, turn it off, because any direct caller could forge the header.
- **CEM invariants.** Re floor stays at 30,000 and confidence at 0.8. `verified_gain` and `manufacturing_ready` stay false. No tolerance, floor or receipt is loosened to make a test pass.
- **Dragster invariants** (master § 5): v1 byte-stable; no LLM in geometry; `ProcessRunner` limits 30 s / 1536 MiB never raised.
- **Sandbox invariants** (CLAUDE.md): `compiler.py`, `script_policy.py` and the allowlists are never edited.
- **Merge order matters.** Every stream edits the workflow radio in `frontend/app.py` and route wiring in `backend/main.py`. Keep both sides on conflict. ## Orchestration framework (reuse this)

Roles:
- **Lead (main session, strongest model).** Owns the plan, briefs, merges and the owner conversation. Never does bulk implementation. Answers only to the owner.
- **Workstream agent (`general-purpose`, sonnet via downshift).** One per stream. It works in its own worktree on its own branch and opens a PR. It never merges, never deploys, never calls a live model.
- **Architect agent (`Plan` or the lead).** Writes design sections before implementation, for anything cross-cutting such as U6 § 5.
- **Security reviewer (`xvant-review-security`, or `mirum-security-reviewer` if available).** Runs on every PR that touches endpoints, `schemas.py`, `compiler.py` or key handling. After fixes, a second reviewer verifies each finding CLOSED / PARTLY / NOT and hunts for regressions.
- **Explore and general-purpose readers.** Read-only fan-out for audits (branch lineage, stale work) when the lead needs conclusions, not file dumps.

Every brief contains:
1. The plan file and section to read first.
2. Worktree path and branch, with "work only there".
3. Numbered steps, tests first.
4. The test commands it may run and where:
   - the host venv `C:\Users\jiang\Mirum-ui\.venv\Scripts\python.exe` has pytest, pydantic, streamlit and numpy, but no fastapi or CadQuery;
   - no Docker;
   - the native suite runs in CI.
5. Hard limits: no merge, no force-push, no deploy, no live model call, no edits to sandbox, tolerances or other streams' files; LF endings; gate (a).
6. Commit trailer and PR body footer.
7. "Write your report before any long CI wait, then append the CI result."
8. Report format: branch, head SHA, PR, commands with counts, exit criteria pass/fail, deviations, what was not verified.

Lead loop:
1. Brief streams in parallel where files do not overlap.
2. On each report, verify the claims yourself (CI, diff stat), never from the report alone.
3. Run a security review on endpoint PRs and send the findings back to the same agent with `SendMessage`.
4. Build a **merge train**:
   - throwaway branch from `main`, merge every ready PR in order, resolve conflicts once;
   - open a draft "CI only" PR and wait for green;
   - merge the real PRs in order, making the conflicting one byte-identical to the train (`git diff --quiet train HEAD`);
   - confirm CI on `main`;
   - delete merged branches, retargeting any stacked PR first.
5. Update plan § 6 and project memory after each merge batch.

CI watching:
- Use `gh pr checks <n> -R Azrkiel/Mirum --json bucket --jq '[.[]|select(.bucket=="pending")]|length'` in an `until` loop with `run_in_background`.
- No `jq`. Make sure checks exist for the new head before trusting a pending count of 0.
- The native gate takes 15–23 minutes.
