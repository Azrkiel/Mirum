## 5. Orchestration design for Wave E

### 5.1 Layers

```
OWNER  approves live calls, keys, deploys, limit changes, E03 family, E04 lab
  |
LEAD (Claude Code, Opus, main session in C:\Users\jiang\Mirum)
  |  writes the phased plan + contract, spawns phase managers, verifies branches,
  |  runs security reviews, merges (sec 5.3 of the 11-20 handoff), reports to the owner
  |
  |-- herdr core (hc): long-lived terminals for managers/workers; status/events/read
  |
  |-- Phase managers (Claude, xvant-phase-manager, one worktree each, max 2 at once)
  |     |-- Claude workers (Agent tool, sonnet; coupled/judgment/security-adjacent tasks)
  |     '-- Codex workers (xvant-codex codex-worker.sh; bounded single-area chunks)
  |
  '-- Reviewers (xvant-review-security / xvant-review-*; read-only, never Codex)
```

**Laptop budget.** Low RAM: background shells get reaped, and Docker or full suites are out locally.
- At most **2 phase managers** at once.
- At most **3 Codex workers** running in total (`CODEX_MAX=3`).
- At most **3 Claude agents** in total, the lead's reviewers included.
- Every command stays under 5 minutes. CI is the test authority.

### 5.2 Codex CLI workers (xvant-codex)

- **Launch only through the script.** Never call raw `codex exec`: it hangs on stdin, gets no sandbox, and leaks env. Never launch Codex directly from `hc run` either.
  ```bash
  bash ~/.claude/skills/xvant-codex/scripts/codex-worker.sh run <name> <workdir> <runroot>/brief-<name>.md <runroot> workspace-write <model>
  ```
- **Models**, both present in `~/.codex/models_cache.json` as of 2026-11-20:
  - `gpt-6.2-sol` for well-specified single-area chunks.
  - `gpt-6.2-astra` for hard or cross-cutting chunks.
  - Do not swap models on failure; report it.
- **Never Codex for:** reviews, merges, secrets or keys, live model calls, B13-style qualification runs, `backend/compiler.py`, `script_policy.py`, allowlists, workflows, Dockerfiles, compose, or `startup_checks.py`.
- **Each worker gets:**
  - its own worktree, `git worktree add -b codex/<name> C:/Users/jiang/Mirum-cx-<name> <phase-branch-head>`;
  - a scope file `<runroot>/scope-<name>.txt` with globs disjoint from every other worker;
  - a brief built from `brief-template.md` with `C:/...` paths and PowerShell-compatible checks (no Python in the sandbox).
- **The worker cannot commit.** Its manager (or the lead) commits after verifying.
- **Verify every worker, in this order:**
  1. Trust only the `## Script facts [<nonce>]` block.
  2. Read the full diff before running anything in the workdir.
  3. Reject worker edits to tests that weaken assertions, to lockfiles or to workflows.
  4. Re-run the checks yourself.
  5. Python tests run in CI only. Push a branch and let CI run.
- **Budget per worker:** 1 resume plus 1 relaunch. After that, a Claude worker or the manager does the chunk, and the report says so.
- **Proven pattern from RC1** (R4 and R6 streams): the Claude stream owner writes a short `harness-contract.md`, then 2-5 Codex workers fill disjoint test or fixture files against it. Merge through the stream owner's branch, never directly to main.

**herdr rules**
1. **Label every terminal** `--label wave=e --label phase=<id>`.
2. **Names:** `pm-<phase>` for managers, `cx-<name>` for Codex wrappers.
3. **Nothing hc reports is evidence.** Verify branches, diffs and CI exactly as without herdr. `idle` is never approval: never auto-approve a permission prompt because a terminal is idle.
4. **Interactive Claude sessions launched through `hc` run with the user's normal permission settings.** Do not pass `--dangerously-skip-permissions`.
5. **A reboot or `hc server stop` kills the agents.** herdr doesn't resume work, so phase state must live in git and in the phase report files (section 5.4), never only in a terminal.
6. **Do not run `hc` and the background Agent tool for the same phase.** Pick one per phase.
7. **Default:** use background Agent calls (`xvant-phase-manager`) for managers. Use `hc` for Codex visibility, plus long manager sessions only when a phase is expected to outlive the lead's context.
8. **Before writing the final report,** `hc ls --label wave=e` must show nothing working, and leftover terminals must be killed and removed.

## 8. What went badly and why

- **Agents stall past ~150-200k tokens or 10 minutes of silence** (the stream watchdog). The #100 agent died after pushing; its work survived only because it committed. Fix: managers commit per task and keep the report file.
- **The GitHub API is flaky from this laptop.** Wrap every `gh` call in a 5-try retry.
- **Background shells get reaped under low RAM.** Use bounded foreground waits, `hc wait`, or the notifications.
- **CI fidelity gap:** the release-images regen smoke runs with `/tmp` at 1 GB, while the release compose uses 256 MiB. So two-run space bugs pass CI. It has not been changed yet (known issue K1).
- **Fly machines auto-stop when only ssh traffic hits them.** Long jobs died mid-run during smoke tests. Drive smokes through Flycast or the public URL, and keep the frontend warm.

## 9. Dead ends already tried

- **Running smoke scripts via `fly ssh console` against localhost:** the proxy sees no traffic, so the machine auto-stops mid-job. Run them from the frontend machine through `http://<api>.flycast` instead.
- **`fly ssh sftp shell` put into a read-only root fails** (`/dev/shm` path didn't persist). Pass scripts base64-encoded in `-C "python -c ..."`, or write to `/tmp` on the frontend.
- **Fixed idempotency keys in repeated smokes:** 409 on a persistent volume. Use unique keys.
- **shared-cpu-4x for regen:** too slow (427 s, deadline exceeded). The owner chose performance-2x.
- **herdr-synapse:** macOS/Linux only. Not usable here.
- **Raw `codex exec` or Codex launched by `hc run codex ...` for real work:** no sandbox flag, stdin hang, env leak. Always use `codex-worker.sh`.
