## 0. Facts that shape the design

- **The backend image ships no code.** `backend/Dockerfile:36-40,70-72` expects `./backend` to be bind-mounted at `/app`.
  - `docker-compose.yml:4,8` builds with context `./backend`, so the build can't see the root locks.
- **A pinned recipe already exists.** `deploy/fly/backend.Dockerfile:1-28` installs the same three locks as `Dockerfile.verify:11-35`, COPYs the source and runs as `USER 10001`. It lacks digests, hashes and guards.
- **The locks pin versions but carry no hashes.** The release only needs pip: `cadquery==2.6.1` and `cadquery-ocp==7.8.1.1.post1` are wheels (`requirements-linux.lock:12-13`), so there's **no conda-lock**.
- **One asset comes from a CDN at runtime.** `frontend/app.py:96-98` loads Babylon.js from `cdn.babylonjs.com`. The page uses it only for LLM `/generate` results.
- **Regen can't produce an accepted run in any current image.** It needs the PicoGK builder at `/opt/regen/app/builder` (`backend/engineering/regen_web.py:43`).
  - That builder comes from `picogk-builder/Dockerfile`.
  - That Dockerfile needs a local `picogk-runtime:26.2` image and a gitignored CA file.
- **Most startup guards already exist.**
  - Worker count: `store.py:27-29`.
  - uid: `store.py:33`.
  - flock owner: `store.py:35-40`.
  - Mounted volume: `api_v1.py:151-153`.
  - Scratch/data separation: `api_v1.py:154-155`.
  - A raise inside `_lifespan` (`main.py:164-169`) aborts uvicorn.
  - Missing: a tmpfs check for scratch, a token check, a gid/mode check, and coded messages.
- **Auth.** The middleware is at `main.py:258-270`, `/auth/check` at `main.py:1744`, and the frontend gate at `app.py:962-976` (`MIRUM_ACCESS_GATE`). There's no `/health`.
- **Fairness quota.** 6 jobs per client per hour (`config.py:96`), kept in memory (`admission.py:31-36`). All browser traffic counts as one client.
- **The AI stack that qualified (B13 run 5, k6):**

  | Item | Value |
  | --- | --- |
  | Python | 3.10.22 |
  | SDK | google-genai 2.8.0 |
  | Model | `gemini-4-hydrogen` |
  | Temperature | 0.4 |
  | Max tokens | 4096 |
  | Thinking level | low |
  | Prompt / schema | `engineering_extraction_v1` / `engineering_proposal_v1` |
  | Image | `sha256:3527bfa6…` |

  The model, prompt and schema are source constants. Parity can therefore only drift through the Python base, the dependency closure, the CA bundle or the environment.
- **PR #31 touches two of these files:** `frontend/Dockerfile` and `backend/main.py`, around the dragster routes.
- **`e2e/` is outside the existing test runs.** `pytest.ini` testpaths and `Dockerfile.verify` don't include it.

## 1. R2: pinned release images

**Decision:** a separate multi-stage `backend/Dockerfile` with the root as build context. It uses the same locks and the same base digest as `Dockerfile.verify`, but isn't a target inside it.
- **Why:** `Dockerfile.verify` carries test-only content and is built by R1's CI.
- **Parity:** enforced by tests instead: lock-set equality, `pip freeze` subset and AI fingerprint equality.

**Backend stages:**
1. **`deps`**
   - `FROM python:3.10-slim-bookworm@sha256:<D>`, where `<D>` is the digest the k6 run resolved.
   - CI asserts `python -V` gives 3.10.22.
   - apt installs version-pinned packages: libgl1, libglu1-mesa, xfoil (Debian's real `/usr/bin/xfoil`, not `mock_xfoil`), libosmesa6 and libgles2.
   - `pip install --require-hashes --no-deps -r requirements-release.lock`, then `pip check`.
2. **`release`**
   - COPY `backend/`, `analysis/` and `output/wing_assembly_oml_reference.json`.
   - `chown 10001:10001` the directory `/tmp/mirum/engineering`.
   - Run as `USER 10001:10001`.
   - `ENV MIRUM_DEPLOYMENT=release MIRUM_ENGINEERING_REQUIRE_VOLUME=1 WEB_CONCURRENCY=1 MIRUM_API_REPLICAS=1`.
   - Start uvicorn with `--workers 1`.
3. **`b13-eval`**
   - `FROM release`, plus `scripts/` and the corpus, with no pip.
   - Not wired into `b13-live.yml` during RC1. That switch belongs to M2 and needs STOP-G and a security review.

**Other R2 parts:**
- **Baseline:** the old conda recipe is kept as `backend/Dockerfile.conda-baseline`. Nothing builds it, and the pin test lists it as non-shipped.
- **Locks:**
  - `requirements-release.lock` (backend) and `frontend/requirements.lock`, both in pip hash mode.
  - `scripts/make_release_lock.py` generates them. It takes the exact `==` pins from the existing locks and adds every file hash for each version from the PyPI JSON API. It runs on the host, deterministically.
  - It never resolves versions.
- **Frontend:**
  - Both `FROM` lines pinned by digest, with the same Python digest as the backend.
  - A hashed lock and `USER 10001`.
  - COPY all of `backend/dragsters/`, which absorbs #31's Dockerfile hunk.
- **Babylon:**
  - New `frontend/viewer_assets/` with `package.json` and `package-lock.json`.
  - A node stage copies the dist files to `/app/static/babylon/`.
  - `frontend/.streamlit/config.toml` sets `server.enableStaticServing=true`.
  - `app.py:96-98` switches to `/app/static/babylon/…`.
- **Dev compose:** the backend build uses context `.`, `dockerfile: backend/Dockerfile` and `target: deps`, with `MIRUM_DEPLOYMENT: development`. Dev bind mounts stay.

**`e2e/test_image_pins.py`** (stdlib only) fails unless:
- every `FROM` and `COPY --from` image is pinned with `@sha256:`;
- every `pip install` uses `--require-hashes` and every lock line has `==` plus `--hash`;
- apt packages are pinned as `pkg=ver`;
- npm runs `npm ci` with a lockfile;
- there is no `conda`, `curl|sh`, `--trusted-host`, `--no-check-certificate`, `PIP_CERT` or `verify=False`;
- the final stage has `USER 10001`;
- the release lock's (name, version) set equals the union of the three backend locks;
- the frontend lock is a subset of `requirements-linux.lock`;
- no `http(s)://` script or link URLs appear in `frontend/*.py`.

**AI parity (an explicit R2 acceptance criterion):**
- `scripts/ai_fingerprint.py` prints JSON containing:
  - `sys.version`;
  - `GeminiProposalProvider().settings()`;
  - the prompt and schema versions (`proposer.py:30-31`, `dragster_proposer.py:26`);
  - the versions in the full `google-genai` dependency closure;
  - the sha256 of the certifi bundle;
  - the sha256 of `proposer.py`, `dragster_proposer.py`, `config.py` and `subagents/model_registry.py`;
  - `ENGINEERING_TLS_OS_TRUST` and the AI environment defaults.
- `e2e/fixtures/ai_parity_reference.json` holds the k6 values above.
- `e2e/test_ai_parity.py` asserts:
  - (a) the release fingerprint equals the `Dockerfile.verify` fingerprint at the same SHA;
  - (b) the release fields equal the k6 reference;
  - (c) the release `pip freeze` is a subset of verify's `pip freeze`.

**CI:**
- `.github/actions/build-release-images/action.yml`, a composite action. It builds both images and records image IDs, base digests and lock sha256 values to JSON.
- `.github/workflows/release-images.yml`.
  - `permissions: {}` at the top; the job gets `contents: read`.
  - Runs on PRs that touch Dockerfiles, locks or the pin test, and on manual dispatch.

**TDD tasks:**
1. Pin test against the current files (fails).

3. Rewrite `backend/Dockerfile`, add the baseline file, update `docker-compose.yml`.

## 2. R3: release compose and startup guards

**Module:** `backend/startup_checks.py`, stdlib only, so it can be tested on the host venv.

```python
@dataclass(frozen=True)
class GuardFailure: code: str; message: str
class StartupRefused(RuntimeError): failures: tuple[GuardFailure, ...]
def evaluate(env, *, mountinfo: str, stat, euid, egid, argv, try_lock) -> list[GuardFailure]
def enforce(env=os.environ) -> None   # no-op unless MIRUM_DEPLOYMENT == 'release';
                                      # logs "MIRUM_STARTUP_REFUSED code=<c>: <msg>" per failure, raises
```

**Failure codes:**

| Code | Refuses startup when |
| --- | --- |
| `engineering_volume_missing` | the data dir isn't an exact mountpoint under `/tmp/mirum` |
| `engineering_volume_owner` | the volume's uid/gid differ from the process's euid/egid, or `mode & 0o022` is set |
| `engineering_volume_in_use` | a non-blocking flock probe fails |
| `multiple_workers` | `WEB_CONCURRENCY`, `UVICORN_WORKERS` or `MIRUM_API_REPLICAS` isn't 1, or argv has `--workers` > 1 |
| `scratch_not_tmpfs` | the scratch dir isn't on tmpfs |
| `scratch_overlap` | the scratch and data dirs overlap |
| `access_token_missing` | the access token is missing or shorter than 32 characters |
| `root_writable` | `/` isn't mounted `ro` |
| `running_as_root` | euid is 0 |

**Hook:** two lines at the top of `_lifespan` (`main.py:164`). An unset `MIRUM_DEPLOYMENT` means development, so the native gate's TestClient runs are unaffected.

**`compose.release.yml`:**
- **backend:**
  - `image: mirum-backend:release` (target `release`), with no bind mounts and `read_only: true`.
  - tmpfs `/tmp` and `/tmp/mirum`, the latter with uid/gid 10001 and mode 0700.
  - The named volume `mirum_engineering:/tmp/mirum/engineering`.
  - `MIRUM_ACCESS_TOKEN: ${MIRUM_ACCESS_TOKEN:?required}`.
  - Port bound to `127.0.0.1:8000`.
  - `cap_drop: [ALL]`, `no-new-privileges`, `init: true`.
  - A healthcheck that calls `/auth/check` with the token.
- **frontend:**
  - The same hardening.
  - `MIRUM_ACCESS_GATE=1` and `BACKEND_URL=http://backend:8000`, on `127.0.0.1:8501`.
  - Healthcheck `/_stcore/health`; depends on the backend being healthy.
- `docker-compose.yml` stays the development configuration.

**Tests:**
- **Unit:** `backend/tests/test_startup_checks.py`.
  - One case per failure code, using injected env, mountinfo fixtures and fakes.
  - A Linux-only case using the real `/proc/self/mountinfo`.
  - A TestClient lifespan refusal case.
- **Docker:** `e2e/test_startup_guards.py`, plus overlays in `e2e/compose/misconfig/`: `no-volume`, `root-owned`, `workers2`, `scratch-disk` and `no-token`.
  - Each overlay must exit non-zero with its failure code in stderr.
  - Multi-owner: a second backend started on the same volume must be refused.
  - The good config must answer `/auth/check` with 200 with the token and 401 without it.
- **CI:** `.github/workflows/release-guards.yml`, using R2's composite action.

**TDD tasks:**
1. Unit tests for each code (they fail).
2. `evaluate` and `enforce`.
3. The Linux real-mount test.
4. The lifespan hook and the TestClient refusal test.
5. `compose.release.yml` and the good-config test.
6. The misconfiguration overlays.
7. The workflow.

**Accept when:** each misconfiguration fails in CI with its specific code, the good config gives 200/401, and the security review is clean.

## 3. R4: CI e2e harness

**`.github/workflows/release-e2e.yml`:**
- **Triggers:** `workflow_dispatch` (input `clean` for the freeze run), and `pull_request` filtered on the `e2e` label.
- **Permissions:** `permissions: {}` at the top and `contents: read` for the job. No secrets. Actions pinned by SHA.
- **Steps:**
  1. Run R2's composite action.
  2. Generate a run-local token with `openssl rand -hex 32`.
  3. `docker compose -f compose.release.yml -f e2e/compose/e2e.override.yml up -d --wait`. The override only renames volumes.
  4. Install hashed `e2e/requirements.lock` (pytest, playwright, httpx), then `playwright install --with-deps chromium`.
  5. Run `pytest -c e2e/pytest.ini e2e`.
  6. On failure, dump compose logs to the job log.
  7. Upload PNG and JSON only.
  8. `timeout-minutes: 45`.

**Layout:**
- `e2e/pytest.ini` and `e2e/conftest.py`.
- `e2e/harness/stack.py`: compose control, health checks, restart per module, digests.
- `e2e/harness/api.py`: an httpx client with the token.
- `e2e/harness/ui.py`: page objects. **All selectors live here.**
- `e2e/harness/evidence.py`: writes `evidence.json` containing:
  - the source SHA;
  - image IDs and base digests;
  - lock hashes;
  - `pip freeze` for each image;
  - the outcome of each test;
  - the list of screenshots.
- `e2e/compose/e2e.override.yml`.
- `e2e/artifacts/` (gitignored).

**Selector strategy (Streamlit 1.39), in order of preference:**
1. Role or label scoped to a section heading.
2. Stable `data-testid` values: `stButton`, `stDownloadButton`, `stAlert`, `stStatusWidget`.
3. `.st-key-<key>`, only once R4 task 1 confirms that 1.39 emits it.

Never use emotion classes or `nth-child`. Wait on text with `expect(...).to_have_text`, because the results view refreshes every second.

R4 may add `key=` arguments, and nothing else, to keyless buttons in `frontend/engineering_ui.py`.

The browser context aborts every request that leaves loopback and records it.

**Tests (B14 step 18):**

| Test | What it checks |
| --- | --- |
| `test_auth.py` | The API returns 401 without the token and 200 with it; the UI gate rejects a wrong token and accepts the right one. |
| `test_beam_reference.py` | `examples/engineering/cantilever.json` typed in. <br>• The review caption's draft, revision and SHA equal what the API returns. <br>• Acknowledge, finalize, run. <br>• Attempts table: 5 and 10 mm rejected, 15 mm accepted. <br>• The "Measured STEP preview" renders (screenshot). <br>• Every download's sha256 matches `GET /jobs/{id}/artifacts/{fmt}` and the ZIP manifest. <br>• A low-allowable variant is rejected, with no preview, no downloads and artifacts refused. |
| `test_generators.py` | Parametrized over dragster, glider and regen: a v1 form draft, then save, acknowledge, finalize and run. <br>• Accepted runs show the "Checked design" label and downloads. <br>• Regen is expected to give an **accepted** run once R2b part 2 lands (§ 6). |
| `test_llm_route.py` | `/capabilities` reports `ai_enabled` and `ai_available` as false. <br>• A beam prompt routes to checked design with a notice. <br>• A non-capability prompt gets an error or unavailable state, with no checked label and no model call. |
| `test_negative.py` | An unsupported capability gets 422 and nothing approximated. <br>• Stale review: a PATCH in tab B, then finalize in tab A, gives 409. <br>• Idempotency: the same key gives the same `job_id`. <br>• Refreshing during a job keeps the job. <br>• Two tabs stay consistent. |

Every flow saves a PNG. The backend restarts per module, which resets the in-memory quota without changing any limit.

## 5. Risks and cheap resolutions

1. **Regen can't produce an accepted run in the release image**, because the builder is missing. Owner decision; see § 6.
2. **The `3.10-slim-bookworm` tag has moved past 3.10.22.** Take the digest from the k6 BuildKit log; old digests remain pullable.
3. **Hash coverage.** Taking every PyPI file per version covers it. `--require-hashes` fails closed and names any gap.
4. **The `st-key-*` class may be missing in 1.39.** R4 task 1 checks. The fallback is role/label selectors plus `key=` edits.
5. **The LLM fallback without a key may be slow or show raw errors.** `test_llm_route` times it. If it takes over 60 s or the wording is unclear, the lead files a small `main.py` fix PR, with security review.
6. **The volume might not initialize as uid 10001.** R3's good-config test catches it. Fix it in the image, never with a root init container.
7. **flock across containers.** The multi-owner test proves it works.
8. **Quota or slowapi limits during e2e.** Restart the backend per module. Any limit override needs owner acknowledgment and is noted in the evidence.
9. **Babylon is never rendered in provider-free runs.** Covered by the static 200 check and the no-URL test.
10. **Parity drift through the environment or the CA bundle.** The fingerprint includes the certifi hash and TLS settings, and compose leaves `MIRUM_ENGINEERING_TLS_OS_TRUST` unset.

## 6. Lead decisions (2026-11-18)

- **`Dockerfile.verify` digest-pin exception: approved.** The change is limited to the `FROM` digest lines, after R1 merges, so the verification and release images share the 3.10.22 base the k6 run used. It tightens a pin and loosens nothing.
- **Regen scope (§ 5 risk 1): owner decision 2026-11-18: regen ships AVAILABLE.** New stream **R2b** builds PicoGK in CI.
  - **Part 1:**
    - The PicoGK runtime (OpenVDB) and the .NET regen builder are built on GitHub runners.
    - Base images are pinned by digest.
    - The Avast CA becomes an optional BuildKit secret: it's for local builds only and is never baked into an image.
    - Builds are cached with the GHA cache, with no registry push.
    - The real `test_regen_*` tests and a reference spec run against the native builder.
    - Workflow `.github/workflows/picogk-runtime.yml`.
  - **Part 2, after R2 merges:**
    - A `regen` stage in the release `backend/Dockerfile` copies the builder to `/opt/regen/app/builder` and the libs to `/opt/regen/lib`.
    - The e2e regen test expects an **accepted** run with the checked-design label.
  - **R2b owns:** `spike-picogk/Dockerfile.runtime`, `picogk-builder/**`, `picogk-runtime.yml` and `backend/tests/test_picogk_dockerfiles.py`.
- **Order:**
  - R2 and R3 tasks 1–4 run in parallel. R3's unit tests and lifespan hook don't need images.
  - R3 tasks 5–7 wait for R2's composite action.
  - R4 follows R2 and R3.
  - Then R5 and R6 in parallel, then R7 and R8.
