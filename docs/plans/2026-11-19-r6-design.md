# R6 design: release storage and process controls (B14 step 19), and B13 step 13

Date 2026-11-19. Architect pass (Plan agent), recorded by the lead. Base: `main` at `081d390`.
Style follows [rc1-design](2026-11-18-rc1-design.md). Docker runs in CI only. Nothing here changes a
limit, tolerance or receipt. Every expiry or failure that is not real is labelled in the evidence:
**R** = real observation, **F** = fault injection, **A** = accelerated timestamp.

## 0. Facts that shape the design

- **Expiry has no knob.** `bundle_retention_seconds = 6*3600`, `state_retention_seconds = 7*86400`
  (`capabilities.py:87-88`), stamped into `jobs.expires` (`jobs.py:223-225`) and `publications.expires`
  (`bundles.py:312-313`). Hosted jobs cap at 6 h, so real expiry cannot be observed in CI. The B10 test
  already accelerates by rewriting the stored timestamp (`test_engineering_bundles.py:99-100`).
- **Legacy cleanup has knobs:** `MIRUM_ARTIFACT_TTL_S`, `MIRUM_ARTIFACT_MAX_RUNS`,
  `MIRUM_ARTIFACT_MAX_TOTAL_BYTES` (`artifacts.py:58-60`); provider-free path `POST /dragsters/generate`;
  namespaces separated at `bundles.py:139-142`.
- **Overall deadline** 420 s, hard-coded (`jobs.py:65-67`, `search.py:42-46,61-68`). Beam native stages time
  out at 30 s; the regen worker at 900 s, so a stalled regen builder is the only way to reach the real
  420 s deadline with the API responsive.
- **Admission has no queue.** One native slot (`admission.py:81-95`, 429 + `Retry-After: 5`); storage check
  `max(reserved, storage_bytes) + run_budget > 512 MiB` or ≥ 50 reserved (`jobs.py:142-147`); regen
  `run_bytes` 256 MiB, others 32 MiB.
- **Quota:** 6 admissions/client/hour in memory (`admission.py:59-66`); slowapi `POST /jobs` 10/min,
  `/dragsters/generate` 5/min. Restart the backend between groups; never auto-retry a 429.
- **Recovery:** on restart non-terminal jobs become UNAVAILABLE (or CANCELLED if cancelled)
  (`jobs.py:80-87`); owner tag rotated and old workers reaped (`jobs.py:91-98`); staging wiped and
  uncommitted accepted directories discarded (`bundles.py:444-457`).
- **Publication:** budget/free-space checks before any write; staged with fsync, `os.replace`, row write,
  full validation; any failure rolls back (`bundles.py:282-323`). Cancel or deadline at commit overrides the
  outcome (`jobs.py:213-216`).
- **Downloads:** in-memory leases; cleanup skips leased jobs; a new lease after expiry gives **410**
  (`bundles.py:390`, `api_v1.py:116-117,377`); polling shows `delivery='expired'`; integrity failure 503.
- **Graceful stop:** `_lifespan` → `jobs.close()`; compose has `init: true`, `restart: "no"`, default 10 s
  grace. Regen workers carry no owner tag (harmless in this topology; LOW). `RLIMIT_FSIZE` breaks .NET, so
  `ulimit fsize` is ruled out for write-failure injection.
- **Replay:** `scripts/checked_engineering_replay.py` replays a beam `package.zip` without AI. Step 12
  kept digests only, not the AI brief bytes.
- **R4 constraints:** `e2e/pytest.ini` collects an explicit list; `release-e2e.yml` allows overrides that
  change volume names only. Slow cases need their own ini, overlays, projects and workflow.

## 1. Test matrix (B14 step 19)

Common post-checks after every disruptive case: **P1** no orphan processes (tini, uvicorn, exec helper
only; nothing holding `MIRUM_PROCESS_TOKEN`, `MIRUM_ENGINEERING_OWNER` or the regen builder); **P2** volume
clean (empty `staging/`, no bundle or publication row for a non-accepted job); **P3** no acceptance (same
idempotency key → same job/state; artifacts 404/503); **P4** recovery idempotent across a second restart;
**P5** slot freed (a fresh beam job is accepted) where quota allows.

## 2. Placement

- **Fast lane (`release-e2e`):** `e2e/test_storage_fast.py` with S01+S05+S06, S07a (beam pair), S12(i);
  about +5 min. Needs one `python_files` line in `e2e/pytest.ini`.
- **Slow lane: `.github/workflows/release-storage.yml`**, `workflow_dispatch` + `pull_request` labelled
  `storage` (same repo only), `permissions: {}` / `contents: read`, SHA-pinned actions, no secrets, masked
  run-local token, JSON/PNG artifacts (`-nonrelease` unless dispatched on main). Jobs (45 min each):
  `lifecycle` (S01-S06), `capacity` (S07-S09, S11), `retention` (S10, S12-S15), `native-on-release` (S16).
  `sudo` only in named steps (loop image, chattr, remount, fallocate, poller). Each overlay is checked by a
  jq allowlist step (`legacy-knobs`: two backend env keys; `staging-tiny`: one tmpfs entry; `small-volume`:
  volume `driver_opts`/`name`); `mem_limit`, `read_only`, `cap_drop`, ports and token never change.

`ops.py` wraps `Stack` (injectable runner/clock/sleep; every command < 290 s; output redacted):
container control (`container_id`, `exit_code`, `kill`, `stop`, `start`, `replace`; never `down -v`),
in-container work (`exec_py` as uid 10001, `processes` from `/proc` reporting only token/owner presence,
`signal`, `api_host_pid`), volume access (`volume_name`, `mountpoint`), a hardened **sidecar**
(`docker run --rm --network none --read-only --user 10001:10001 --cap-drop ALL --security-opt
no-new-privileges --tmpfs /tmp -v <vol>:/tmp/mirum/engineering[:ro] mirum-backend:release python -c …`:
`db_rows` with `query_only`, `set_expiry` (records an "A" note), `volume_digests`, `write_sparse`, `remove`,
`tamper`), and host helpers (only `sudo -n` users, gated on `CI=true`: `host_poll_then_stop`,
`host_chattr`, `host_fallocate`, `host_remount`).

`storage_flows.py`: `beam_brief`, `regen_brief` (draft → finalize, every review field acknowledged),
`submit` (never retries), `wait_for`, `artifact_digests`, and `CaseLog` writing
`e2e/artifacts/storage/<job>/storage-cases.json` (case id, mechanism, kind, `expiry_accelerated`,
observations, source SHA, image IDs).

## 6. Risks and decisions

Risks: timing windows (S01, S02, S04b, S10: poll for state + worker presence, regen for long windows, host
SIGSTOP for S04b, loud failure, no silent retry); quota/rate limits (restart between groups, ≤ 6
admissions per segment, never retry 429); memory/disk (regen 2.4 GB peak, one stack per job); cross-container
SQLite writes (WAL + busy_timeout, timestamp/tamper targets only); nested tmpfs leaves a root-owned mountpoint
(S08b on a throwaway volume); graceful stop can become SIGKILL (S02 records elapsed; R7 documents it); sudo on
hosted runners (named steps, no secrets, same-repo PRs).

Decisions (lead applied the recommended defaults on 2026-11-19 under the owner's "continue" instruction; none
loosens a product limit; the owner may override):
1. Expiry acceleration: rewrite stored timestamps via the sidecar, labelled "accelerated" (A). No product knob.
2. Legacy knobs `MAX_RUNS=1`, `TTL_S=1` in a test overlay (tightening, labelled): approved.
3. `sudo` on hosted runners, `release-storage` only: approved.
4. S08c read-only volume: if the 500 + non-terminal-until-restart behaviour is confirmed, record a LOW known
   issue and document it in RELEASE.md (restart recovery already prevents acceptance); a fix (map
   `sqlite3.Error` to 503) would be a separate reviewed PR.
5. Replay source: the release stack's typed reference brief (same `brief_sha256` as step 12's identity
   check); no new live call.
6. V14 failure views: add S15.
7. Step 13 closes on the R8 freeze evidence (same runs as B14 steps 19/22).
8. S16 existing tests on the release image: yes.
9. Keep S03 (the only real observation of the 420 s deadline).
10. Fast lane: S01, S07a, S12(i) in `release-e2e`; move S12(i) to the slow lane if R4 exceeds 38 min.
