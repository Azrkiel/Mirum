## Goal and accepted result

With `MIRUM_ENGINEERING_AI_DRAFTS` on, `POST /engineering/v1/drafts` with `mode='ai'` works for
`co2_dragster`, `regen_chamber` and `glider_cem` through one capability-agnostic path that obeys
`backend/engineering/proposal_contract.py`. Out-of-family or ambiguous requests end as `unsupported` or
clarification, never a substituted capability. The beam's B13-qualified path is unchanged.

## Changes and integration surface

- `backend/engineering/regen_proposer.py` (new): `AiProposer(budget, provider=None)`. Typed extraction into
  `RegenChamberSpec` through the beam's `GeminiProposalProvider` (imported, not edited). Prompt version
  `regen_extraction_v1`, one repair call, one budget unit per call (never refunded), 16 KiB reply cap, strict
  JSON. Unstated fields come from a preset (`policy`, `preset:<name>`); stated ones are `ai_proposed`/unverified.
  Refusal (`refuse_regen`) comes before clarification.
- `backend/engineering/glider_proposer.py` (new): `AiProposer(budget, extract=None)` wraps
  `cem.extraction.extract` unchanged (lazy import). **calibration_version policy:** the shipped initial snapshot,
  `cem.glider.calibration.version(calibration.initial())`, origin `policy`. A prompt that mentions a calibration
  or flight-test update, or an unreadable snapshot, makes the field a clarification. The model never supplies it.
  Families left at `all` become a clarification. Thermal or ridge environments and unsupported families are `unsupported`.
  Requirement leaves equal to the `GliderMissionRequirements` defaults are `policy`; the others are `ai_proposed`.
- Both new proposers run `router.route()` first. A prompt routed to another capability is `unsupported` with no
  call and no budget unit.
- `backend/engineering/api_v1.py`, generator `mode='ai'` branch of `create_draft`, in this order:
  1. Flag off: 503 `AI draft preparation is not enabled`.
  2. The prompt must be at most `MAX_PROMPT` characters (2000).
  3. **Family gate:** a route to another capability gives an `unsupported` draft; an `Ambiguous` route gives a
     clarification draft. Neither makes a call or uses a unit.
  4. The shared beam `AiCallBudget` (`value.proposer.budget`) needs capacity, else 503 `unavailable` before any
     call.
  5. Quota admit with `ai=True`.
  6. `proposal_contract.ai_proposer` → `propose` → `conform`. A `NonConformingProposal` or `unavailable` result
     returns 503 with the existing unavailable shape.
  7. Otherwise the draft is created from the payload, issues and provenance.
- `job_view` adds `claim`: `checked_design` (beam), `geometry_checks_only` (dragster, regen) or `screening_only` (glider).
- Offline corpora: `backend/tests/fixtures/engineering/proposals/{co2_dragster,regen_chamber,glider_cem}-v1.json`.
- Zoo investigation (card step 3): `../proposals/E05-zoo-backend.md` (docs only; no integration).

## Remaining risks and blockers

Security review of PR #109 (2026-11-20) - fixed on this branch:
- M1 fixed: every unit a generator AI request reserves is written to the additive `generator_spend` table
  (capability id, request sha, timestamp; no prompt or reply) before the provider call, and
  `SQLiteProposalLedger.recent_calls()` reads it, so a restart re-seeds beam + generator spend. Reserve-then-crash
  is counted; a failed spend write fails closed (`backend/engineering/store.py` `GeneratorSpendBudget`).
- M3 fixed (fail closed): `cem.extraction.extract` uses the legacy global `google.generativeai` client, which
  `main.py` configures from `GEMINI_API_KEY_PRO` (fallback HEAVY). When PRO is set and differs from
  `GEMINI_API_KEY_HEAVY`, the glider proposer returns `unavailable` before reserving budget or calling extract.
  Residual: anything else that later calls `genai.configure()` with another key would still change the glider's key.
- LOW-5 fixed: glider provenance labels by origin. The real extraction output is fully default-filled, so every
  requirement leaf is `ai_proposed` (unverified); only `calibration_version` is `policy`.

Accepted residuals:
- M2 (shared budget, no per-client sub-quota): same as the B13-qualified beam design. One client is bounded by
  20 unfinalized drafts and 10/min with <=2 calls per draft; prod flag off; qualification runs as one client.
- LOW-4: a router no-match prompt reaches the model; the output is still fail-closed by `conform` and the
  proposers' family checks.
- LOW-6/7: recorded from the review as low; no change on this branch.
- The glider proposer reserves one unit even when `extract` answers a deterministic clarification without a
  provider call (over-counts, never under-counts).
- The spend record is a small synchronous SQLite insert on the event loop thread at each reserve.
