## Goal and accepted result

Close the E02 audit gaps: screening never reads as acceptance in the API, UI or package; the adapter recomputes the design revision; the selected family, process and calibration state are surfaced; `/cem` behavior is pinned.

## Changes and integration surface

- `frontend/engineering_v1.py`, `engineering_v1_ui.py`: labels and messages come from the capability `claim` (`claim_of`, `accepted_label`, `result_heading`, `outcome_message`). Glider = "Screened ... not accepted for manufacture; not engineering certified"; dragster/regen = "Geometry checks passed"; beam wording unchanged.
- `backend/engineering/bundles.py`: generator `report.md` heading and Outcome line follow `claim`. The internal job outcome value stays `accepted`, as does the `report.json` outcome; beam package output is untouched. Dragster/regen heading changes from "Checked ... result" to "Geometry Checked ... result".
- `backend/engineering/glider_adapter.py`: `design_revision_sha256` is recomputed (identity from the report, parameters/process from the selected elite, placement from the bundle `design.json`) and compared against both the report and the bundled design; mismatch is a binding failure. New `selection` key in the package report: `family` (from `parameters.tail.kind`: conventional/T/V -> conventional/t_tail/v_tail), `process`, `calibration_state`.
- Tests: `frontend/test_engineering_v1.py`, `backend/tests/test_engineering_glider_labels.py`, `test_engineering_glider_closure.py`, `test_engineering_glider_adapter.py` (fixtures now carry a real revision), `test_cem_compat_e02.py`.
