# F10 qualification handoff

The release candidate keeps the existing MEL beam profile and the v0.1 and v0.2 operation registries. The bay uses an additive v0.3 registry and pins its kernel, catalog, numerical limits and native environment. PicoGK MEL addresses the existing `reference` preset and exposes only the registered STL format. Switching a capability, catalog, backend or native lock requires a new reviewed revision.

## Replay contract

`mirum_program_replay_v0_1` captures an available, verified published beam, bay or PicoGK preset revision via the normal HTTP exports. It includes exact MEL source, ProgramIR, execution lock, operation and check plans, a verification receipt and the original delivery ZIP. The inner ZIP retains the reviewed brief, attempts, manifest, reports and exact artifacts. Each byte sequence is digest-bound. Capture refuses an expired package and does not overwrite an archive. The v0.1 replay archive uses a 64 MiB file cap. PicoGK retains its larger pinned expansion budget for delivered meshes.

```sh
PYTHONPATH=backend python -m engineering.program.replay capture REVISION_ID accepted.zip
PYTHONPATH=backend python -m engineering.program.replay verify accepted.zip
PYTHONPATH=backend python -m engineering.program.replay verify accepted.zip --measure
```

Capture takes `MIRUM_API_URL` and the configured access token from the same environment as the ProgramClient. Offline verification recompiles the source and checks record and file identity. Native verification additionally requires the original reviewed native lock and rereads the STEP or STL. Migration uses a new stage and review. Rollback uses the existing restore operation while the original artifacts remain available. Turning off the workspace feature flag withdraws the new editor entry point.

## Release evidence

The product smoke in `scripts/phase3_bay_release.py` exercises nominal promotion, digest-bound STEP and BOM, archive replay, rejected substitution and head preservation in the pinned image. CI also runs the existing PicoGK reference through MEL and records the geometry-only evidence scope. The native HTTP tests cover the same bay route, unit equivalence and an interrupted admission followed by rebuild. The receiving fixture passed in FreeCAD and the independent Part 21 reader.

Actual provider equivalence, the complete browser gate and the hosted product-image results determine release qualification. The release remains on the feature branch. The existing public enablement and retention gates apply.
