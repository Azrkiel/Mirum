## Goal and accepted output

MEL v0.1 frontend ([task card](../tasks/F04-language-frontend.md)) in the new package `backend/engineering/language/` (F01 D9):

- `diagnostics.py`: `Diagnostic(code, category, message, hint, span, field)`, `Span`/`Position` (0-based byte offset, 1-based line and column in Unicode scalar values, end inclusive; `Span.to_source_span()` gives the F02 `SourceSpan`), `MelError` (one diagnostic), the MEL-L and MEL-P code tables with a hint per code. Messages echo at most 64 characters of source with non-printables escaped.
- `lexer.py`: hand-written single-pass lexer implementing every frozen lexical rule (LANGUAGE.md sections 1-8). Whole-input checks in order: size (L022), BOM (L002), strict UTF-8 (L001); a pre-scan finds the first NUL (L003) or bidirectional control (L006) and the error at the smallest position wins (a NUL/bidi error wins a tie). Token budget 10,000 excluding the end marker (L023).
- `syntax.py`: frozen dataclasses `Program`, `Assignment`, `Quantity` (number text kept exactly as written), `String` (decoded), `ListValue`; spans do not take part in equality.
- `parser.py`: recursive-descent parser for the LANGUAGE.md grammar with MEL-P codes and the FRAMEWORK.md budgets: depth 16 (program 1, assignment 2, value 3, each list level +1; checked before descending, so recursion is bounded), 2,000 syntax nodes (program, assignments, every value), 256 elements per list. A unit is the identifier directly after a number on the same line.
- `formatter.py`: canonical formatter (below).
- `lower_beam.py`: provisional beam-only lowering (`compile_beam`, `lower_program`) to ProgramIR; F05 replaces it with the general semantic compiler.

A keyword (`language`, `mirum`, `design`) where a name is expected is MEL-L008 (lexical category), as the frozen table says.

Formatter style: header line; `design <name> {`; one assignment per line indented two spaces as `name = value;`; lists inline `[a, b]`; a quantity is its number text exactly as written, one space, the unit; strings re-escaped as ASCII JSON (non-ASCII, control and DEL characters become backslash-u escapes, so the output always lexes and never carries a raw bidi control); LF endings and one trailing newline. Comments are dropped: the formatted text is a new source with its own source hash, while its syntax tree and semantic hash are unchanged. format is idempotent. A formatted file can exceed 64 KiB when the input is near the limit and heavily non-ASCII (escaping grows it); it then fails L022 like any oversize source.

Lowering (beam only): the AST is mapped field by field (an explicit table, no defaults, unknown fields rejected) to the same `engineering_brief_v1` payload the typed form sends, validated by the existing `BriefService.validate`, turned into ProgramIR by the F02 bridge `program_from_brief_content`, and sent back through `brief_content_from_program` before hashing (K32), so language and form meet at one reviewed `BriefContent`. Quantities use `program.units.normalize` (mm/cm/m/in, N/kN, Pa/MPa/GPa; mass is never force). `material_source_kind` uses the frozen identity table. capability must be "rectangular_cantilever" 1.0.0, backend "occt", exports exactly step and glb (bridge rule). Source spans (assignment name through `;`) are attached to requirements and the candidate parameter; the program span is the design block. Semantic failures carry the F02 IR codes (IR002, IR005, IR006, IR007, IR010) with category `semantic`, the MEL field name and its span; F05 owns the final MEL-S table.

## Blockers and limitations

- The lowering is beam-only and provisional; F05 owns general semantic compilation, MEL-S codes, review and the execution-lock resolution.
- First error stops (frozen v0.1 rule); there is no error recovery for editors yet (F09).
- `5em` lexes as number 5 with unit `em` (an `e` not followed by digits or a signed digit ends the number); unit lookup is semantic.
- Process note: the Write tool turned backslash-u escape text into real characters while writing a test file (including a bidi control). The test files now build non-ASCII with `chr()`, and `test_language_sources_are_ascii` keeps the package ASCII; reviewers should grep diffs for non-ASCII.
