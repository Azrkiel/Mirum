## Goal and accepted output

Implement and qualify the kernel adapter framework ([task card](../tasks/F03-kernel-adapters.md)) for the F01 D8 matrix: rectangular_cantilever 1.0.0 on OCCT (CadQuery) and regen_chamber 1.0.0 on PicoGK.

- `backend/engineering/program/kernel.py`: the KernelAdapter protocol and its records (pydantic `IRModel`: strict, frozen, extra forbidden, finite floats), schema version `mirum_kernel_v0_1`.
  - `describe() -> BackendDescription`: backend `occt`|`picogk`, adapter version, mode `native`|`mock`, representations, export formats, tolerance conventions (each with the existing source it was read from), supported `capability@version` and `operation@version`.
  - `async probe() -> ProbeResult`: observed native versions; metadata alone is not readiness (OCCT builds a 1x2x3 box in an owned subprocess and checks its volume; PicoGK uses the existing `regen_web._ready()` plus runtime/builder file digests and the runtime manifest).
  - `supports(plan) -> SupportDecision`, `async build(plan, context) -> Built`, `async inspect(artifact, plan) -> InspectResult`, `export(artifact, format) -> ExportResult`. `BuildPlan` (D2) = capability id/version, backend, the existing domain candidate (`CandidateSpec` / `GeneratorCandidate`), exports, and a planned F02 `OpStream` (`plan_for` builds the canonical one with optional ProgramIR spans).
  - `ExecutionContext`: deadline, artifact byte budget, workspace label; no credential, path or env field.
  - `BackendLock` (separate from the unchanged `ExecutionLock`): backend, adapter version, mode, probed native versions, representations, export formats, tolerances. `backend_lock()` refuses an unavailable or mock probe. F05 folds it into a new lock version.
  - Outcomes: `unsupported` (reasons capability_not_supported_by_backend, backend_mismatch, export_not_supported, operation_not_executable, operation_not_supported, plan_invalid, candidate_invalid), `unavailable` (runtime_missing, probe_failed, busy, deadline_exceeded, native_failed, evidence_invalid, budget_exceeded, mock_backend), `precision_failure` (measurement_out_of_tolerance, reread_mismatch). Each reason field is a Literal of its own allowlist (fails closed).
- `adapters/occt.py`, `adapters/_occt_probe.py`, `adapters/picogk.py`, `adapters/mock.py`, `adapters/__init__.py` (`adapter_for(backend, mode=...)` returns exactly that backend's adapter; no fallback).
- Registry `mirum_operation_registry_v0_2` (lead decision D3), op stream and ArtifactGraph emission (D4), native conformance (D5), offline snapshots (D6), D8 rejections (D7).

## build123d conformance note (F01 D2: evaluate, not adopt)

build123d was not installed or imported; this is a written evaluation against the code at d8f430d.

- API mapping for the qualified beam envelope: the beam source is `cq.Workplane("XY").box(L, W, H, centered=(False, False, False))` (`engineering/spec.py:build_source`). build123d equivalent: `Box(L, W, H, align=(Align.MIN, Align.MIN, Align.MIN))` (algebra mode) or `with BuildPart(): Box(...)`. Volume `part.volume`, bounds `part.bounding_box()`, STEP `export_step(part, path)`, GLB `export_gltf(part, path, binary=True)`. The reread path (`verification.solid_set.inspect_step`, `verify.verify_step`) reads the STEP through OCCT and is independent of the authoring API.
- What would change: `build_source` and the sandbox allowlist in `backend/compiler.py` (`_ALLOWED_MODULES` admits `cadquery`/`cq` only), the dependency locks (`requirements-linux.lock` and `requirements-release.lock` pin `cadquery==2.6.1` and `cadquery-ocp==7.8.1.1.post1`; build123d pins its own `cadquery-ocp` range), the native image, and the OCCT probe script. The adapter, records, op stream and ArtifactGraph would not change: they wrap the beam path, not the authoring API.
- Risks: a security-critical sandbox allowlist change; an OCP version conflict that could move B-rep tolerances and the pinned STEP/GLB digests of the golden beam; a second authoring API in the image with no capability gap it closes for the D8 matrix; topology naming is the same OCCT naming either way, so semantic identity (FRAMEWORK) gains nothing.
- Finding: no conformance gap in the D8 envelope that build123d would close. Keep CadQuery/OCP for v0.x (F01 D2 stands); revisit only for MEL v0.2 construction ops (sketch/extrude/fillet), with its own decision, lock bump and golden re-qualification.

## Blockers and limitations

- The registry export file keeps the name `mirum_operation_registry_v0_1.json` while holding v0_2 content, because `schema_export.py` (`REGISTRY_EXPORT_NAME`) is outside F03's owned files. Recommended follow-up (lead/F05): export `REGISTRY_V0_1` under the v0_1 name and `DEFAULT_REGISTRY` under a v0_2 name.
- Main 93e29d4 (K30/K31 PR #131, F04 PR #133) was merged into the branch without conflicts; `schema_export --check` passes on the merged tree.
- Found by native CI and fixed: (1) `verify_step` stops at `size_requirements` before recording its measurements, so a STEP reread against the wrong dimensions first came back `unavailable`/`evidence_invalid`; `compare_reread` now maps a failed dimensional check of the independent reader to `precision_failure`/`measurement_out_of_tolerance` with that check's own evidence. (2) The real small.json STL exceeds 64 MiB, so a 64 MiB test context gave `unavailable`/`budget_exceeded` (correct behaviour); the native test now uses `REGEN.resources.run_bytes`.
- PicoGK readiness is the existing `_ready()` file/executable check plus file digests; a real build only happens in `build()`. A busy JobRunner slot surfaces as `unavailable`/`native_failed` (the existing `RegenAdapter` does not distinguish it), not `busy`.
- PicoGK build measurements are what the existing `parse_report` exposes with a mappable unit (bbox max error in mm); the ratio-valued volume measurement is skipped rather than relabelled. The STL reread reports measured bbox and volume.
- OCCT native tests skip on non-posix hosts (ProcessRunner needs POSIX process groups) as well as without cadquery.
