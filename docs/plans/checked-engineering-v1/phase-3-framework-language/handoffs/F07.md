## Goal and accepted output

Bind semantic beam features and reviewed checks to the exact delivered STEP and GLB ([task card](../tasks/F07-independent-verification.md)). D1-D12 below are the lead's decisions for this phase.

- D1-D4: The pure check-plan builder takes reviewed IR, the v0_2 execution lock and the reviewed candidates. It fixes each candidate's checks, requirement and feature references, representations and limits before measurement. Selection uses the job row's `selected_candidate_sha256`. The binder uses the closed-solid count and geometric predicates for `beam.solid`, `beam.root_section` and `beam.free_end`. Face signatures store normal, center and area. Order and names have no role in binding. Zero matches means missing, multiple matches means ambiguous, and both block verification of a required feature.
- D5 and D12: The verifier validates the committed job's bundle and hash-checks capped leases of `model.step`, `preview.glb`, `report.json`, `selected_spec.json` and `attempts.json`. An owned native worker measures the leased STEP with OCP and parses the leased GLB with bounded reads and traversal. The worker returns a face table of up to 64 faces and a mesh summary. A per-verifier semaphore serializes measurements.
- D6: Required geometric checks need measured coverage against the plan in the required representation. The evidence records the representation, numerical error bound, coverage and method for same-kernel reread (`same_kernel_reread`). Native versions must match the lock. `physics.report_inputs` cross-checks report section inertia, length and height against the measured geometry under `policy_report` coverage. Manufacturing and standards remain `not_evaluated`. Evidence verdicts are `verified`, `failed`, `ambiguous` and `unavailable`.
- D7-D9: `policy.assess` determines acceptance. The default `RevisionService` verifier runs only after policy acceptance and job commit. It can withhold promotion with `delivered_check_failed`, `delivered_binding_ambiguous`, `delivered_evidence_unavailable`, `delivered_unverified` or `delivered_evidence_stale`. The evidence row is committed before settle and checked for a match inside the promotion transaction. `recover()` uses stored evidence and never measures. It can roll forward with matching verified evidence; a missing row gives `delivered_unverified`. Restore requires the target's verified row for its job and bundle or gives `record_altered`. Restore uses the original evidence without measuring and permits earlier method versions.
- D2 and D10: Delivered revision verification is beam-scoped. PicoGK evidence maps the qualified adapter's inspect output to `geometry_checks_only`, and glider evidence maps screening output to `screening_only`. Each excludes beam and manufacturing acceptance labels and keeps physics and manufacturing `not_evaluated`. Mock measurements cannot verify a revision.

## Files and interfaces changed

- `program/evidence.py` defines the pure records, check-plan builder, geometry-only binder, evaluator and PicoGK/glider label mappers. `versions.py` declares CheckPlan `mirum_check_plan_v0_1` and DeliveredEvidence `mirum_delivered_evidence_v0_1`. `schema_export.py` registers both models, with committed JSON schemas in `backend/engineering/program/schemas/`.
- `program/delivered.py` adds `DeliveredVerifier`, `EvidenceStore` and `method_version()`. The method version hashes the name-sorted file digests of `evidence.py`, `delivered.py` and `adapters/_occt_measure.py`. `EvidenceStore` revalidates rows on read.
- `program/adapters/_occt_measure.py` is the native measurement worker. The additive async `OcctAdapter.measure(artifact_step, artifact_glb, plan)` takes a `BuildPlan` and returns a `MeasureOutcome` with a face table, mesh summary and failure reasons as available. The `KernelAdapter` protocol keeps its F03 interface.
- `program/transactions.py` adds the `verifier` keyword to `RevisionService` with a real, fail-closed `DeliveredVerifier` by default. `evidence(revision_id, *, client)` resolves through `evidence_revision_id`, including for restores. It checks client ownership like `view()` and returns the revalidated record or `None` when the row is absent or the gate is disabled.
- The legacy job and bundle formats stay as in F06. Delivered evidence lives in the revision store. The Python service is the integration point for F08.

## Migration and rollback

`EvidenceStore` creates the additive `program_evidence` table with `CREATE TABLE IF NOT EXISTS`. It adds no foreign key and leaves `PRAGMA user_version` at 1. Reverting F07 leaves the additive table unused. With F07 active, a restore target needs its original matching verified row.

## Blockers and limitations

- The frozen F06 journal detail-key pattern `^[a-z_]{1,32}$` excludes digits. The published event uses `evidence_hash` to carry `evidence_sha256` of the row.
- `GLB_LINEAR_DEFLECTION_MM` records the 0.1 mm default linear deflection in CadQuery 2.6.1 `Assembly.save(exportType='GLB')` (`cadquery/assembly.py`, lines 513-514). That bound exceeds the reviewed 0.01 mm size tolerance. `delivered.preview_extent` can fail definitively, pass conservatively when the tolerance permits, or return `not_evaluated` with `bound_exceeds_tolerance`. For `beam.mir` the check is optional and cannot establish size. A measured failure blocks verification even for this optional check. Substituted, scaled, empty and unparsable previews fail. The native `test_glb_frame_convention_is_pinned_on_a_known_box` uses a 1x2x3 box to pin the CadQuery (x, y, z) mm to glTF (x, z, -y) mapping and node transform with no unit scaling. P10 preview fidelity at 0.01 mm stays `not_run` (lead default Q3).
- A non-verified record produced before the bundle is read carries the `UNKNOWN_SHA256` placeholder. A verified record always carries actual hashes. Verified rows are never overwritten.
- The 60 s overall bound covers validation, leases, cross-checks and measurement.
- PicoGK and glider mappings use declared limit refs under `policy:regen.<REF>` and `policy:glider.<REF>`. Beam limit sources remain the reviewed requirements and beam numerical policy.
- A spec, attempts or report cross-check failure records `physics.report_inputs` as `failed` with `report_mismatch`.
