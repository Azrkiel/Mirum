## Goal and accepted output

Define Mirum's typed engineering program and operation registry ([task card](../tasks/F02-typed-ir.md)). New package `backend/engineering/program/` (module boundary frozen in F01 D9):

- `versions.py`: version identifiers (below).
- `errors.py`: `ProgramError(code, message, field, span)`, `Diagnostic`, `IRModel` (extra forbidden, strict, frozen, finite floats only) and `SourceSpan` (1-based, end inclusive).
- `units.py`: dimension-checked normalization for length (mm, cm, m, in -> mm), force (N, kN -> N), pressure/modulus (Pa, MPa, GPa -> MPa), mass (kg, g -> kg), time (s, ms, min -> s), angle (rad, deg -> rad) and dimensionless ('1'). Decimal arithmetic as in `contracts.Quantity.normalized`; deg uses float(math.pi)/180. No mass-to-force conversion.
- `ir.py`: `ProgramIR` = schema_version + design name + `CapabilityRef` + `RequirementPlan` (normalized quantities or text, semantic ids) + `CandidateSpace` + `AnalysisPlanRef`s + `ConstructionGraph` (reserved, must be empty in v0.1) + `EvidenceExpectation`s + `ExecutionSelection` (backend, exports) + `ProgramProvenance` (form | ai | language, source hash) + optional source spans on every record. `ExecutionLock` and `execution_lock(ir)`. Strict loader `load_program_json` / `program_from_dict`.
- `hashing.py`: four independent hashes (source, semantic, execution lock, artifact) and the canonical JSON rule.
- `registry.py`: `OperationDescriptor` (id, version, typed args with dimensions, preconditions, outputs, representations, backend requirements, capability versions, executable), `OperationRegistry`, `DEFAULT_REGISTRY`, construction-graph and call validation; D7 records `OpStream`/`OpStreamEntry` and `ArtifactGraph`/`ArtifactNode` with `load_artifact_graph_json` (no producer; F03 emits them).
- `beam_bridge.py`: lossless translation between the reviewed beam `contracts.BriefContent` (rectangular_cantilever 1.0.0) and `ProgramIR`.
- `schema_export.py` + `schemas/`: committed JSON Schemas generated from the models and the registry export (D6).

## Migration and rollback

None for stored data: no runtime path reads or writes ProgramIR yet. Rollback is reverting the F02 commits. A future IR change must take a new schema_version; `load_program_json` rejects unknown versions with IR001 rather than reinterpreting them.

## Blockers and limitations

- Candidate value order is significant in the generic semantic payload. The beam contract sorts and deduplicates heights (F01-INVENTORY V3), so programs lowered through `brief_content_from_program` -> `program_from_brief_content` are normalized; F05 must lower .mir through the bridge (or apply the capability's normalization) before hashing.
- Text values are hashed as given; the contract strips whitespace on the way back. F05 should normalize text through the contract before computing the reviewed semantic hash.
- The schema-only CI job installs pydantic unpinned but does not run the schema test; the native image pins 2.9.2. A pydantic upgrade requires regenerating `schemas/` (`cd backend && python -m engineering.program.schema_export`).
- ConstructionGraph and the construct.* descriptors are records only; MEL v0.2 must be specified before any G1 execution (F01 D1).
