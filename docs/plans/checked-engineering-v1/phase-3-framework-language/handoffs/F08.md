## Goal and accepted output

Expose the F06 revision service and F07 evidence gate through four interfaces that reach the same checks. [F08 task card](../tasks/F08-interfaces.md)

- D1-D3 put the Python SDK in one in-process `ProgramInterface` over `RevisionService`, `BriefService`, `PreparationQuota` and `ProgramQuota`. In deployment, only the API process holds a `RevisionService`. The CLI and MCP server use the HTTP SDK. Import-pin tests exclude the store, `sqlite3`, `fastapi`, `httpx` and native modules from those clients. CLI `--offline` is limited to validate, format and plan, which share the server's `offline.py` functions.
- D4-D6 wire the runtime into the API lifespan. The additive routes inherit `no-store`, ID masking and the access-token gate. The route snapshot pins the original `/engineering/v1` route set from `F01-DECISIONS.md:111`. The program flag defaults off.
- D7 uses a shared structured error envelope. A policy rejection returns HTTP 200 with `result_kind: rejected`. Verifier outcomes are results with `result_kind: unavailable` or `verification_failed`.
- D8 closes K48. Human review supplies `brief_sha256`, `acknowledged_fields` and `reviewed_by`. The server resolves the draft from the client-checked revision. Run resolves the finalized brief for that revision's draft, and responses omit `draft_id`, `brief_id` and `job_id`.
- D9 closes K46. `ProgramQuota` derives per-client usage from `programs.client` in SQL and uses the existing tables. Defaults are 8 programs, 4 staged revisions across all programs, 32 stage/rebuild operations per rolling 24 h and 2 MiB of payload bytes. `MIRUM_ENGINEERING_PROGRAM_MAX_PROGRAMS_PER_CLIENT`, `MIRUM_ENGINEERING_PROGRAM_MAX_STAGED_PER_CLIENT`, `MIRUM_ENGINEERING_PROGRAM_MAX_STAGE_OPS_PER_CLIENT_DAY` and `MIRUM_ENGINEERING_PROGRAM_MAX_PAYLOAD_BYTES_PER_CLIENT` use fail-closed parsing and can only tighten the defaults. Stage, propose and rebuild share one non-queuing slot. Validate, format and plan use a non-queuing `Semaphore(2)` and compile in a thread. Full slots return 429 `busy`.
- D10-D11 close K47. The facade calls `RevisionService.expire_staged` in the mutation prelude. Missing or tombstoned drafts and staged rows that reach the draft TTL move to `failed` with `review_expired`. Rows being admitted are skipped. `transactions.py` also moves stage and run compilation into `asyncio.to_thread` and adds client-checked `source()` for the evidence revision's source, IR and lock exports. A compacted payload returns 410.
- D12 exposes MCP tools `validate`, `format`, `plan`, `propose`, `status`, `inspect`, `history`, `diff`, `run` and `cancel`. Create, review, restore, rebuild and export are outside that tool set. `propose` sends the head's `fixed_requirements_sha256` as `X-Mirum-Require-Requirements`. A missing head or hash mismatch gives `requirements_changed`. Tool schemas exclude path, URL and directory arguments. F08 makes no provider calls, and the source scan checks the new modules for `proposer`, `proposal_contract`, `AiCallBudget`, `genai` and `GEMINI` references.
- D13 restricts the CLI to the named source file. The server comes from `--url` or `MIRUM_API_URL`. The token comes only from `MIRUM_ACCESS_TOKEN`, and the client omits `X-Mirum-Client-IP`. The HTTP SDK refuses redirects and caps JSON responses at 4 MiB. Export verifies `X-Content-SHA256`, writes `<out>/<allowlisted name>` atomically and refuses existing files and symlinks.
- D14 makes run idempotent per client with one job per revision. Once a revision leaves `staged`, run returns its record. Polling and export do not admit jobs, probe, build or measure.
- D15 keeps public enablement blocked on K51. Under D16, Claude workers wrote tasks 1-6 (including the task 1 fixtures; Codex was optional there and unused), and Codex drafted these docs, reviewed by the phase manager.

JSON schemas are committed under `backend/engineering/program/schemas/`.
- `program/facade.py` implements the in-process SDK. `program/offline.py` implements shared validate, format and plan. `program/client.py` is the HTTP SDK using stdlib `urllib`. The CLI runs as `python -m engineering.program.cli` and the stdio JSON-RPC server as `python -m engineering.program.mcp`.

## Migration and rollback

`api_programs.py` reads `MIRUM_ENGINEERING_PROGRAMS`, which defaults off. With the flag off, the program runtime is absent, startup creates no program tables and requests that reach the program routes receive 503 `programs_disabled`. Construction failure logs `engineering.programs construction_failed`, disables the program runtime and leaves legacy v1 routes available. Tests enable the flag through their environment. Deployment and CI configuration leave it off. Disabling the flag removes program service access on restart.

## Blockers and limitations

- K51 blocks enabling `MIRUM_ENGINEERING_PROGRAMS` in public production. `revision_store.py` counts all rows against its lifetime 256-program cap, and the journal prevents deletion. Retention needs a separate fix. The flag stays off.
- The registry has 16 entries, including MCP-only `propose` alongside the 15 operations. `GET /mel/meta`, `GET /programs/{pid}` and `GET /programs/{pid}/journal` are secondary routes on `validate`, `history` and `inspect`.
- Added kinds are `invalid_request` (422), `unauthorized` (401) and `programs_disabled` (503). The inherited access-token gate returns its established 401 detail body. `service_unavailable` is the fallback code. The error table includes `verifier_unavailable`, while verifier outages surface as results (`unavailable` or `verification_failed`).
- Review acknowledgements allow dotted field names such as `material.youngs_modulus_mpa` from `REVIEW_FIELDS`.
- The per-client payload quota checks stored payload bytes plus the incoming source length.
- To keep the lifespan change in one hunk, `main.py` builds the program runtime after the regen import, just before `regen_lifespan`. A nested `try/finally` closes the program service before `jobs.close()`.
- Program creation and revision staging return 201. The facade reads exports under a byte cap in place of `api_v1.LeasedResponse`. Slots and quotas bound load without per-route limiter decorators.
- MCP returns `not_found` for malformed ID-shaped arguments and JSON-RPC `-32600` for batches. Tool descriptors carry `readOnlyHint`.
