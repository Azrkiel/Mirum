# F09 handoff

The opt-in Streamlit MEL workspace uses the F08 program routes for diagnostics, plan preview, staging, human review, execution, comparison, exports and restore. Enable the frontend with `MIRUM_PROGRAM_WORKSPACE=1` and the backend with `MIRUM_ENGINEERING_PROGRAMS=1`. The existing checked form remains available. Open an existing program with its program ID after a browser reload.

A browser editing session holds an expected parent. If another tab promotes a revision, staging requires loading the current source or explicitly updating the authoring base. Saved preview bytes are checked against both the download fingerprint and the selected revision bundle. Cancel and restore go through the existing revision service.

The beam AI input uses the existing typed draft provider route and its budget. The workspace translates a complete typed draft to MEL, validates it with the compiler and requires a separate user action to stage it. MEL created this way is recorded with the `typed-ai-proposal.mir` source label. The server compares the candidate's compiled fixed requirements with the accepted head's guard before creating a review. A proposal can change allowed candidate choices under that guard. Human review and the ordinary execution policy govern publication.
