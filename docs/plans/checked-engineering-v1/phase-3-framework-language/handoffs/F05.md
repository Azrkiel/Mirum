## Goal and accepted output

Compile MEL programs into reviewed executable engineering plans ([task card](../tasks/F05-compiler-and-review.md)):

- `backend/engineering/language/semantic.py`: `compile_source(source: bytes | str, *, source_id=None, deadline_s=2.0, clock=time.monotonic) -> CompiledProgram`. The result is a frozen record with these fields: `ir` (ProgramIR), `brief_content`, `source_sha256`, `semantic_sha256`, `brief_sha256`, `spans` (field -> Span, then the design block), `language_version` "0.1", `compiler_version` `mirum_mel_compiler_v0_1` and `diagnostics=()`. A failure raises `MelError` with one diagnostic. The pipeline is LANGUAGE.md stages 1-4:
  1. Parse with the unchanged F04 lexer and parser.
  2. Look up the field schema by exact capability@version (`CAPABILITY_SCHEMAS`).
  3. Normalize, type-check and envelope-check each value.
  4. Build the canonical IR through `BriefService.validate -> program_from_brief_content -> brief_content_from_program`. The round-trip BriefContent must equal the validated one before any hash is taken, or MEL-S017 fails the compile closed (K32).
- Final MEL-S table: see [LANGUAGE.md](../LANGUAGE.md), "Frozen in F05". `diagnostics.MEL_S_IR_CODES` is a frozen MEL-S -> IR code map, and `Diagnostic.ir_code` carries the IR code.
- Deadline (D5): the call is the post-admission point. The deadline is checked cooperatively with the injected clock at every stage boundary and once per assignment and per list element. When exceeded, it raises MEL-S018 with category `resource`. A `deadline_s` outside (0, 2.0] raises `ValueError` (caller misuse).
- K34: a bad `source_id` raises `MelError` MEL-S016, never a plain ValueError.
- `lower_beam.compile_beam` and `lower_beam.lower_program` are thin wrappers that return identical ProgramIR. The F04 field tables are re-exported.
- `backend/engineering/program/planning.py` (LANGUAGE.md stages 5-7):
  - `plan_program(compiled, *, mode, adapter_factory=adapter_for)` calls `adapter_for(ir.execution.backend)` exactly once. Candidates come from the reviewed BriefContent and are checked by the CandidateSpec validator. Plans come from `kernel.plan_for` with ProgramIR spans. If `adapter.supports` does not accept a plan, the result is a typed `PlanRefusal` carrying the SupportDecision. No backend is iterated or substituted.
  - `lock_program` probes once, builds the BackendLock and returns ExecutionLock v0_2. A mock backend is refused as `mock_backend`.
  - `open_review` creates the draft through the existing `BriefService` (no new store), and the existing `finalize` reviews it.
  - `authorize_run` and `run_program` form the run gate. It refuses before any `adapter.build` unless all of these hold:
    - the brief is finalized for that draft revision;
    - its digest equals the compiled brief_sha256;
    - the semantic hash matches;
    - the review holds a v0_2 lock, and its hash equals the lock built from a fresh probe (otherwise `unavailable`/`lock_mismatch`, meaning re-review);
    - the existing `CantileverAdapter.candidates` reproduces the planned candidates.

  Acceptance stays in `policy.assess`, which runs inside the existing evaluation. The adapters copy its verdict.
- ExecutionLock v0_2 `mirum_execution_lock_v0_2` (`kernel.ExecutionLockV0_2`, which lives in kernel.py because it embeds `BackendLock` and kernel imports ir):
  - It holds every v0_1 field plus `language_version`, `compiler_version` and the native `BackendLock`.
  - `ir.execution_lock_v0_2(ir, backend_lock)` builds it and `hashing.execution_lock_v0_2_sha256` hashes it.
  - `ir.load_execution_lock_json` reads both versions by `schema_version` and returns IR001 for anything else.
  - It has a new schema file, `mirum_execution_lock_v0_2.schema.json`.
- K35: `schema_export` writes `mirum_operation_registry_v0_1.json` from `REGISTRY_V0_1`, byte-identical to the F02 export (sha256 `0f20ac6e522e485b787ecc2e54feb55def59868ec13ceea574ae1c4d932c54df`, pinned). It also writes the new `mirum_operation_registry_v0_2.json`.
- K37: `PicogkAdapter.inspect` rereads the STL on a module-owned `ThreadPoolExecutor(max_workers=1)` behind a lock acquired without waiting, so a busy slot returns `unavailable`/`busy`.
  - The worker thread frees the slot, so a timed-out reread keeps it. Hostile repeats get `busy` and can never occupy more than one thread or the default executor, which probe uses.
  - The inspect deadline is `INSPECT_DEADLINE_S = 20 s`, below `REGEN.resources.overall_seconds` = 420. On this PR, picogk-runtime measured the real reread of the small cleaned STL (68,073,484 bytes) at 1.804 s (run 45002982642, under a provisional 120 s), so 20 s keeps a margin above 10x. `test_regen_native_k37.py` re-measures the reread on every picogk-runtime run and requires at least 5x.

## Blockers and limitations

- regen_chamber is not compilable in MEL v0.1 (MEL-S011, tested). Its reviewed input path (`BriefService.validate` -> `GeneratorBriefContent`, every `RegenChamberSpec` field required, no defaults) could be targeted by an explicit field table. The F02 bridge `beam_bridge.py` carries only the beam, though, so a regen ProgramIR cannot pass the K32 round trip without a new reviewed bridge. Follow-up: a regen bridge, a field table and a PicoGK planning path (owner: lead / a later task).
- K37 deadline: the main picogk-runtime log (run 44991110075) had no per-test reread time (19 tests in 300.01 s), and scipy is missing on the host. The deadline therefore comes from this PR's own native timing test: 1.804 s in run 45002982642, with a 20 s deadline. Repeated hostile inspects still each occupy the single reread thread for up to the reread time. They cannot queue, though: any extra inspect gets `busy`.
- The OCCT native tests (`test_program_adapter_occt_native.py`, `test_program_compiled_beam_native.py`) error at collection on this Windows host because its OCP install is partial. They run in the CI native shards.
- Policy fields (`numerical_policy`, `resource_policy`) accept only the registered value for the capability. A changed policy is therefore a compile error rather than an invalidated review, and both outcomes block execution.
